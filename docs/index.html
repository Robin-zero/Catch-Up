Features

为「一直在追」的人，做的一点整理

不追求社区、评分榜和推荐流。只把记录、找回、补全这几件事做顺，让下一次点开时不用重新回忆。

一步，就是一级进度

列表和网格里都能直接 ±1。进度环、状态标签与总进度实时联动，看完最后一集自动收尾成「已完成」。

五种内容，一套进度

剧集、番剧、综艺、电影、短剧；集数与部数分别计数，季数可以留空。

一眼找到它

搜索标题与平台，叠加类型、状态筛选，再按最近更新、添加时间、标题或评分排序。

搜索 类型 状态 4 种排序

删除也留后路

软删除进回收站，可恢复、可彻底删除；支持多选批量删除。墓碑记录让旧数据不会借同步“复活”。

启动就是对的颜色

浅色、深色、跟随系统；启动前预判主题，深色模式下不再有白屏闪一下。

浅色 深色 跟随系统

信息补全，不用手填

条目可以先建再补：多源检索片名、年份、评分、简介与海报，候选确认后才写入，避免污染已有内容。封面可以缓存到本地，断网也能看到海报。

Sync

换一台设备，接上同一条进度线

桌面端支持可选的 WebDAV 同步。远端只保留一份 JSON 快照与一个封面目录，不依赖任何账号体系。

  1. 01

    打开即对齐

    应用启动时先读取远端 catchup-sync.json，与本地条目逐条合并，再进入内容库。

  2. 02

    改完，等 2 秒

    新增、编辑、调进度都算写操作。写入后 2s 防抖再上传，连续操作只会同步一次。

  3. 03

    也可以手动同步

    顶栏按钮随时触发，状态实时显示：等待同步、同步中、已同步（带时间）、同步失败。

  4. 04

    整条覆盖，按时间取胜

    同 id 的条目比较 updatedAt，新的一方整条覆盖旧的一方；不同条目各自保留。

WebDAV 远端结构 
catchup-sync.json   # 条目快照 + 墓碑标记
catchup-covers/
├─ 深海回声-s2.jpg
├─ 第七封信.jpg
└─ 星轨列车-s1.jpg
墓碑防复活：删除会留下记录，另一台设备的旧快照不会把它重新带回来。
封面按文件名去重：上传前查清单，下载后立即登记，重复同步不再重传同一张海报。
只在桌面端启用：浏览器模式使用 localStorage 与 IndexedDB，适合快速预览，不承担多设备同步。
Stack

轻量的壳，扎实的本地数据

界面用 React 与 TypeScript，桌面能力交给 Tauri 与 Rust，数据落在 SQLite 里。

界面

  • React 19
  • TypeScript 5.9
  • Vite 7
  • 原生 CSS 变量 主题系统

桌面与数据

  • Tauri 2
  • Rust 1.77.2+
  • SQLite rusqlite
  • WebView2 / WKWebView 系统内核

同步与工具

  • WebDAV reqwest + rustls
  • Excel 导入导出 calamine / rust_xlsxwriter
  • 测试 Vitest + cargo test
  • 打包 Windows / macOS / Linux
Get Started

两条命令，跑起来看看

需要 Node.js 与 Rust 环境。桌面模式会先启动 Vite，再由 Tauri 打开原生窗口。

快捷键

常用动作都留了键盘入口，双手不用离开键盘。

CtrlN新建条目 CtrlF聚焦搜索 Esc关闭对话框
npm run dev浏览器模式，端口 14200
npm run dev:desktop桌面端开发与热更新
npm run build构建前端静态资源
npm run typecheckTypeScript 类型检查
npm test运行 Vitest 测试

npm install

# 打开桌面窗口
npm run dev:desktop

# 启动开发服务器
npm run dev
